# 蓝牙状态读取与验证

`main.lua` 加载 `user/ble_server.lua`，启动BLE广播。沿用服务UUID `FA00`、通知特征 `EA01`、写入特征 `EA02`，广播名称为 `LuatOS`。固件需支持 `bluetooth` 和 `ble` 服务端接口。

手机连接后先订阅 `EA01` 通知，再向 `EA02` 写入协议中的 `0x00` 连接命令（二进制数据，不是十六进制文本）。模块校验包头尾、长度、地址、帧类型、数据 `01` 和CRC后，先回复连接应答，再上报一次整柜快照：

- `0x01`：电柜信息，15字节数据域。
- `0x02`：逐仓上报仓门信息，9字节数据域。
- `0x03`：逐仓上报电池信息，37字节数据域，按协议字段表合计长度生成，未采用文档表头中的 `09`。
- `0x18`：逐仓上报仓控板版本，2字节数据域。

CRC沿用工程的CRC16-Modbus，低字节在前；状态数值高字节在前。设备地址使用 `attr.setup_get("Device_ID")`，连接请求允许本柜地址或全 `FF` 地址。每条通知最多20字节，手机需按数据域长度重组完整协议帧；接收也支持分片和连续报文。

湿度、电池物理在位、已充电量、预计充满时间当前没有数据源，填 `FF`；原始充电器状态转换为协议的 `0/1/2`（依据电池SOC和充电电流）。24字节旧BT码保留原码并在末尾补两个 `FF`。断开后清除会话和发送队列，重新广播。手机未开启通知或发送失败时，可重新发送连接报文请求快照。

从工程根目录运行：`lua tests/test_ble_server.lua`。测试模拟BLE事件和收发接口；实机需验证固件能力、手机通知订阅及分片重组。
